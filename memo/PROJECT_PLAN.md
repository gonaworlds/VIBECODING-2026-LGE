# 📚 Markdown 문서 편집 사이트 개발 계획 (Obsidian 스타일)

## 🎯 목표
로컬 환경에서 작동하며, Obsidian과 유사한 고급 기능을 갖춘 Markdown 문서 편집기 웹사이트를 구축합니다. 파일 읽기, 쓰기, 실시간 미리보기를 핵심으로 합니다.

## 🛠️ 기술 스택
*   **HTML:** 페이지 구조 정의.
*   **CSS:** 스타일링 (Obsidian과 유사한 깔끔하고 기능적인 UI).
*   **JavaScript:** 핵심 로직 처리 (Markdown 파싱, 파일 I/O, UI 상호작용).
*   **Markdown 파서:** Markdown 텍스트를 HTML로 변환하는 라이브러리 또는 커스텀 로직.

## 🗺️ 개발 로드맵 (Phases)

### Phase 1: 기본 골격 및 핵심 기능 (MVP)
1.  **프로젝트 구조 확정:** `index.html`, `style.css`, `script.js` 등 기본 파일 구조 정의.
2.  **UI 구성:** 편집기 영역(왼쪽/위)과 미리보기 영역(오른쪽/아래)을 분리하여 배치.
3.  **Markdown 파싱 (기초):** 입력된 Markdown 텍스트를 기본적인 HTML로 변환하여 미리보기에 표시. (예: `# Heading` -> `<h1>`)
4.  **상태 관리:** 현재 열려 있는 파일의 내용을 JavaScript 변수로 관리.

### Phase 2: 파일 I/O 및 영속성
1.  **파일 열기 구현:** 사용자가 로컬 파일을 선택하여 편집기에서 열 수 있도록 구현 (File API 활용).
2.  **파일 저장 구현:** 편집된 내용을 로컬 파일 시스템에 저장할 수 있도록 구현 (Blob/File API 활용).
3.  **실시간 동기화:** 타이핑 시 지연 없이 미리보기가 업데이트되도록 구현.

### Phase 3: Obsidian급 고급 기능 구현
1.  **다중 문서 지원:** 파일 탐색기/목록을 구현하여 여러 `.md` 파일을 관리하고 전환할 수 있도록 구현.
2.  **내부 링크 처리:** `[[Link Name]]` 형식의 링크를 감지하고, 내부 파일 목록을 검색하여 클릭 가능한 링크로 변환 (실제 탐색 기능 포함).
3.  **프론트매터 (Frontmatter):** 파일 상단에 YAML 형식의 메타데이터를 지원하고, 이를 파싱하는 기능 구현.

### Phase 4: 검토 및 배포 준비
1.  **테스트:** 모든 핵심 기능(파싱, 저장, 열기, 링크)에 대한 엣지 케이스 테스트 수행.
2.  **성능 최적화:** 대용량 파일 로딩 시 렉(Lag) 방지 및 메모리 관리 검토.
3.  **최종 문서화:** 사용 가이드 및 README 작성.
